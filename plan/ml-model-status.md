# ML model status — Phase M1

## Scope and decisions

Phase M1 adds **two real, trainable models** to the existing full-stack plan rather than
replacing the deterministic pipeline. Both are **disabled by default** and stay behind
configuration flags, so the documented regex/fuzzy baseline and the API contract are
unchanged. This extends `plan/services-optimization.md` (service abstraction) with the
modelling work that was previously listed only in the `MODEL.md` roadmap.

Models were chosen in this order:

1. `medicine-corrector` — character n-gram TF-IDF + logistic regression classifier that
   maps OCR-style medicine misspellings to canonical catalogue names.
2. `prescription-ner` — small spaCy NER model for `MEDICINE`, `STRENGTH`, `FREQUENCY`,
   `DURATION` and `FORM` spans.

A trained image-level OCR/CRNN is deliberately **not** attempted: no labelled prescription
image dataset exists, so such a model could not be validated honestly. All data in this
phase is synthetic and derived from the authoritative medicine catalogue and fixed
templates. No PHI is involved.

## Reproducible data

Generated by `python scripts/generate_model_data.py` with seed `20261127`:

| Dataset | Output | Samples | Train / validation / test |
| --- | --- | ---: | --- |
| Medicine typo classifier | `backend/data/model/medicine_typos.json` | 288 | 202 / 43 / 43 |
| Prescription NER | `backend/data/model/ner_samples.json` | 1200 | 840 / 180 / 180 |

- The typo set uses exact names plus one of five deterministic character operations
  (substitute, delete, adjacent swap, insert, split) on catalogue names/generics/aliases.
- The NER set uses five line templates (plain, labelled, numbered, free text, `Rx`) with
  exact character offsets for each entity label.
- Splits are shuffled with the configured seed; the test split is never used for fitting.

Generated datasets and trained artifacts are gitignored and can be recreated with the
commands below.

## Training and measured results

```powershell
cd backend
python scripts/generate_model_data.py

```

Results measured on this machine on 2026-11-27 (synthetic held-out splits only):

| Model | Validation | Test | Notes |
| --- | --- | --- | --- |
| `medicine-corrector` v1.0.0 | accuracy / precision / recall / F1 = 1.0000 | accuracy / precision / recall / F1 = 1.0000 | 43 test samples, 12 catalogue classes |
| `prescription-ner` v1.0.0 | precision / recall / F1 = 1.0000 (754 spans) | precision / recall / F1 = 1.0000 (757 spans) | 12 epochs, dropout 0.2, exact span match |

These values are 1.0 because both the labels and the corruptions/templates are generated
from a small closed vocabulary. They are **not clinical accuracy claims** and say nothing
about real prescriptions, handwriting or unseen medicine names.

Metrics cards are written next to the artifacts:
`backend/data/models/medicine_corrector.json` and `backend/data/models/prescription_ner.json`.

## Runtime integration

- `backend/config/model.yaml` holds all flags, paths, thresholds and training parameters.
- Medicine corrector: when `medicine_corrector.enabled=true`, a confident prediction
  (probability ≥ `min_score`) is blended into the existing fuzzy/phonetic score only when
  the suggested name is present in the active repository. It never replaces the fuzzy
  result and falls back silently if the artifact or sklearn/joblib is missing.
- NER: when `ner.enabled=true`, `trained_ner` is appended to the configured extractor list
  and the strategy switches to `merge` so the regex stage cannot shadow it. Missing spaCy
  or model files are logged and skipped; scans never abort.
- `GET /api/model-info` now includes `trained_models` with version, enabled/available
  status, method, metrics and the synthetic-data note. Existing fields are unchanged.
- Frontend `ModelPanel` fetches `/api/model-info` and displays model status and held-out
  test metrics alongside the disclaimer.

## Tests

`backend/tests/test_models.py` covers config defaults, deterministic split generation,
corrector thresholds/availability, matcher blending safety, NER label mapping, artifact
training output and the model-info endpoint. Full suite: `python -m pytest -q`.

## Limitations and next steps

- No real labelled dataset: clinical claims remain out of scope.
- No image-level trained model: printed-text OCR still uses Tesseract/EasyOCR/PaddleOCR.
- Artifacts are local only; a deployed instance must run the training scripts or mount the
  generated `backend/data/models/` directory before enabling the flags.
- Next experiment: compare the corrector-enabled matcher against the fuzzy baseline on
  the existing `backend/data/eval_samples.json` via `scripts/evaluate.py`, then consider
  held-out templates with unseen aliases before any OCR/CNN work.
