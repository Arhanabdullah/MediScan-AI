which parts are actually necessary for the current project stage, and how
model optimization is measured. It complements `CLAUDE.md` and the 10-week
plan in `Readme.md` (project currently at Levels 6-7).

### Phase 2 - OCR Multi-Backend Support

| Plan task | Implementation |
|-----------|----------------|
| 2.1 Engine implementations | `backend/app/services/ocr/`: `base.py`, `tesseract.py`, `easyocr.py`, `paddleocr.py`, `demo.py` (heavy deps imported lazily) |
| 2.2 Registry pattern | `OCRRegistry` with `register`, `get`, `best_available`, `configured_order` in `ocr/__init__.py` |
| 2.3 Config-driven selection | `backend/config/ocr.yaml`: priority, per-engine options, preprocess mode and fallback; `OCR_BACKEND` accepts any engine name or `auto` |
| 2.4 Benchmark harness | `backend/scripts/benchmark_ocr.py` computes CER/WER; synthetic images generated by `scripts/make_fixtures.py` |

Additional full-pipeline optimization support:
- `config/matching.yaml` exposes fuzzy-match thresholds and the score curve; `config/confidence.yaml` exposes weights and per-engine OCR scores.
- `scripts/tune_pipeline.py` sweeps `strength_bonus` (macro precision/recall/F1) and grid-searches confidence weights (MAE).
- Preprocessing now has `threshold` and `enhanced` variants; the selected engine declares its preference.
- Normalization and fuzzy scores are cached; the medicine vocabulary is normalized once at startup.

API contract is unchanged. `POST /api/scan` additionally echoes `X-Correlation-ID`.

## 3. Model-optimization process (repeatable)

1. Generate fixtures: `cd backend && python scripts/make_fixtures.py` (synthetic text only, no PHI).
2. Measure OCR: `python scripts/benchmark_ocr.py` - CER/WER per installed engine.
   Install Tesseract system-wide and optionally `pip install easyocr paddleocr`, then
   compare: `python scripts/benchmark_ocr.py --engines tesseract,easyocr,paddleocr,demo`.
3. Tune matching: `python scripts/tune_pipeline.py` - top-1 accuracy and macro P/R/F1
   across `strength_bonus` values; adopt a change only if it improves the measured score.
4. Calibrate confidence: same script grid-searches weights/penalty against labelled
   synthetic cases and reports MAE. A suggested weight set is reported but never
   auto-applied; apply via `CONFIDENCE_WEIGHTS` only after validation on real data.
5. Re-run `pytest` after any config or code change.
